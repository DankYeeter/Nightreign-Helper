# T-003 — Sicherheitsaudit

## Ziel
Angriffsflaeche des Programms vollstaendig bewerten. Das Werkzeug ist public
auf GitHub, wird als PyInstaller-Artefakt verteilt und liest fremde
Binaerdateien (Spielarchive, Savefiles) auf dem Rechner des Nutzers.

## Kontext
- Arbeitskopie: `C:\Users\Daniel\Desktop\ClaudeCode\Nightreign-Helper`, Stand 3da8428.
- Das Programm parst selbstgeschriebene Binaerformat-Leser:
  `nrdata/bnd4.py`, `nrdata/dvdbnd.py`, `nrdata/param.py`, `nrdata/paramdef.py`,
  `nrdata/tae.py`, `nrdata/savefile.py`. Handgeschriebene Parser auf
  nicht-vertrauenswuerdigem Input sind der Hauptverdacht.
- `vendor/` enthaelt eingebundene Fremd-Repos (Paramdex, SoulsFormatsNEXT, UXM,
  WitchyBND). Pruefe, ob und wie daraus Code oder Daten zur Laufzeit gezogen
  oder ausgefuehrt werden.
- Das Programm behauptet: Save wird **read-only** geoeffnet, es gibt **keinen
  Netzwerkzugriff**, keine Telemetrie. Verifiziere beide Behauptungen im Code,
  statt sie zu glauben.
- `nrplanner/shortcut.py` legt offenbar einen Startmenue-Eintrag an — Schreiben
  ausserhalb des eigenen Datenverzeichnisses ist zu pruefen.
- `scripts/` enthaelt Werkzeuge, die moeglicherweise externe Prozesse starten.

## Vorgaben
- Bewerte jeden Befund mit Angriffspfad (wer kann was liefern) und
  Behebungsrichtung. Prioritaet kritisch / hoch / mittel / niedrig.
- Beachte das realistische Bedrohungsmodell: der Angreifer liefert eine
  praeparierte Datei (Save, Relikt-Export, Spielarchiv), nicht Netzwerkverkehr.
- Pruefe die Abhaengigkeiten aus `requirements.txt` auf bekannte Probleme und
  auf Notwendigkeit.
- Pruefe, ob Pfade aus Dateiinhalten je zum Schreiben oder Oeffnen benutzt
  werden (Path Traversal beim Entpacken von Archiven).

## Testumgebung
Windows 10, statische Analyse. Du fuehrst nichts aus, was schreibt.

## Scope-Grenzen
- NICHT: Code aendern.
- NICHT: die `vendor/`-Fremdprojekte selbst auditieren — nur die Art, wie
  dieses Projekt sie einbindet.

## Rueckgabeformat
Befundliste mit ID (SEC-###) im Bericht. Der Director uebertraegt sie nach
`security/findings.md` — schreibe die Datei nicht selbst.

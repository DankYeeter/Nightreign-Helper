## Ziel 1 — die Unterscheidung wird pruefbar statt beschrieben

`nrplanner/advisor/types.py:229-240` traegt zwei leere `str`-Unterklassen:

```python
class ChosenDirection(str):
    """The direction the player is asking about. The answer is about it."""

class PoolOrder(str):
    """The direction that merely put a list in order -- never one to draw in."""
```

Der Kommentar darueber sagt, die Unterscheidung sei *"enforced rather than
hoped for"*. **Sie ist es nicht.** Eine leere `str`-Unterklasse laesst sich
gegen die andere nicht pruefen, ohne `isinstance` von Hand zu schreiben, und
jeder gewoehnliche `str` geht ueberall durch. Das ist genau die Sorte
Zusicherung, die dieses Projekt in QA-233 schon einmal bezahlt hat: eine
Erwartung, die die eigene Unterklasse durchliess.

**`enum.StrEnum`** macht daraus eine Unterscheidung, die der Code halten kann.

**Die Aufgabe ist aber nicht "ersetz zwei Klassen".** Sie ist: **halte die
Aussage, die der Kommentar macht** — dass eine Richtung, die nur sortiert hat,
nie als gewaehlte gelesen werden darf (Nachtrag IX-2). Wenn `StrEnum` das
nicht traegt, weil die Werte aus der Zielrichtungs-Registry kommen und nicht
feststehen, **dann sag das und lass die Klassen stehen.** Ein Widerspruch mit
Begruendung ist hier das bessere Ergebnis als eine Umsetzung, die die Aussage
verliert.

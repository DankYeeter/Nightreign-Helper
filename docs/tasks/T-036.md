## Teil 1 — QA-085 (P2, muss zuerst)

**Keine Signalverdrahtung des Arsenal-Tabs ist gehalten.**
`self.upgrade.valueChanged.connect(self.recalculate)` streichen laesst
**alle Tests gruen** — die Spinbox bewegt dann keine Zahl mehr.
`tabs.currentChanged.connect(...recalculate())` streichen laesst ebenfalls
alles gruen — der Tab bleibt auf den Attributen stehen, mit denen er gebaut
wurde. **Das ist QA-001 woertlich zurueck.**

Grund: jeder Test und die Messstrecke rufen `recalculate()` **selbst**, bevor
sie lesen. Geprueft wird die Rechnung, nie der Ausloeser.

**Fix:** ein Testfall, der ausschliesslich das Bedienelement bewegt
(`setValue` / `setCurrentWidget`) und danach **ohne eigenen
`recalculate()`-Aufruf** die gerenderte Kachel liest. Beide Mutationen
(Spinbox-Connect weg, Tab-Wechsel-Connect weg) als benannte Eintraege in
`scripts/differential/mutate.py` registrieren — das ist ihr natuerlicher Ort,
sie sind schon dort gefunden worden.

Die vom `qa-engineer` gemeldeten drei verwandten Bedienelemente
(`usable_only.toggled`, `rarity_box.currentIndexChanged`, der Such-Debounce)
sind **nicht gemessen**, nur als dieselbe Klasse vermutet — pruef sie, wenn
du ohnehin dort bist, sonst benenn es als offen.

## Teil 3 — QA-086 (gezielt, nicht verbreitert)

**Zwei Faelle, nicht mehr:**
1. Eine **mehrtypige** Armatur vollstaendig gegen `damage.candidate` pruefen
   — alle Typzeilen, "Upgraded to +n Rarity".
2. Der **Rarity-Filter** gegen die Zaehlung in der Zusammenfassung: ein Band
   waehlen, die gezeigte Zahl gegen eine unabhaengig gezaehlte Erwartung
   halten.

**Nicht tun:** die Zauber-Sektionen bekommen **keinen** Waechter — sie zeigen
Zahlen direkt aus dem Datensatz, ohne Rechnung. Schreib stattdessen einen
Satz in den Code, der das begruendet: *diese Zahlen sind ungerechnet; wird
eine davon je gerechnet, braucht sie einen Waechter.* Das ist die Lehre aus
QA-064/070/073/083 angewandt auf eine Nicht-Handlung.
